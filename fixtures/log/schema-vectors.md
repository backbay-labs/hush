# Log schema vectors

`schema-vectors.json` is generated by `scripts/generate_log_schema_vectors.py`.
Run `python3 scripts/generate_log_schema_vectors.py --check` to verify it is
current; generation requires the Python development dependencies, including
`jsonschema[format]` for asserted RFC 3339 date-time validation.

The generator reads the published log-entry schema as its oracle. It builds
full valid entries for all four entry types and mutates each present member's
type, presence, enum/constant, string pattern, minimum length, or integer
minimum. Timestamp cases also cover impossible calendar dates and disallowed
precision, offset, and suffix forms. Every closed object gets an unknown key.

All 471 cases carry correctly recomputed SHA-256 hashes over canonical JSON.
The generator uses independently sorted JSON, restricted to ASCII and small
integers; the four SDK test suites also check those hashes with their own JCS
implementations. Four controls are valid and 467 cases are schema-invalid.
Rust and Python independently revalidate every case against the published
schema with format assertions enabled. All four SDKs check verifier outcomes.

The entry hash itself is not mutated because a malformed hash cannot also be
correctly recomputed. Existing chain vectors cover hash corruption. Receipt
contents remain opaque to the log schema and retain their separate receipt
schema checks and fixtures. Signature controls test envelope structure without
key material; existing signed log vectors exercise cryptographic verification.
